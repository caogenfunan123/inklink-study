# Code-Debug-Review - 代码复盘与根因排查规范

## 适用范围与基准
- **适用项目**：InkLink-Pet (Kotlin Android, 普通彩色手机，非墨水屏)
- **基准规范**：`.monkeycode/specs/pet-system/design.md`

## 核心使命
收到 Bug、异常现象、错误日志或异常行为时，执行深度代码复盘并定位根本原因；严禁简单打补丁掩盖问题。
坚决遵循核心架构：`InkForegroundService` 是唯一真相源，UI 严禁直接篡改业务数据。

## 排查工作流（强制顺序）
1. **收集信息**：复现步骤、表象现象、完整日志与报错堆栈；信息不足时明确指出，禁止脑补猜测 Bug。
2. **分层归类**：
   - 编译错误
   - 业务逻辑错误
   - 并发 / 协程 / Flow 时序竞态
   - Android 生命周期与资源泄漏
   - 网络消息、协议、幂等、离线队列时序问题
   - ROM 行为：服务被杀、电池限制、权限异常
3. **时序梳理**：标出异常节点；通信问题必须画出消息收发时序图。
4. **定位根因**：剥离表面现象，直击深层逻辑缺陷。
5. **最小风险修复**：给出针对性改动方案，评估潜在回归风险。
6. **输出回归用例**：提供明确的测试步骤验证 Bug 不复发。

## 项目专属检查清单（复盘必检）
- [ ] **架构防线**：是否存在 UI 直接修改业务数据的违规行为？
- [ ] **Flow 收集生命周期**：`SharedFlow` 是否在生命周期结束时正确解绑？
- [ ] **Service 生命周期**：前台服务资源与监听器是否在合适时机释放？
- [ ] **消息去重机制**：`IdempotentController` 滑动窗口是否生效？
- [ ] **存储边界保护**：离线队列（上限 50）与任务队列（上限 20）是否存在无限膨胀风险？
- [ ] **网络零信任校验**：外部输入参数是否完成本地截断与类型保护？
- [ ] **音频与 TTS 释放**：`LocalTtsManager` / `SoundEffectManager` 是否在 `onDestroy` 正确释放？
- [ ] **JSON 容错防御**：反序列化是否具备默认值与空安全保护？
- [ ] **高危指令鉴权**：HMAC-SHA256 签名与 $\pm 60$s 时间戳防重放路径是否完整？

## 禁止行为
1. 禁止盲目重写大段代码，必须先分析根因。
2. 禁止使用空 `try-catch` 吞掉异常掩盖 Bug。
3. 禁止随意更改 `design.md` 定义的协议与数据结构契约。
4. 禁止忽视偶发 Bug，必须分析时序竞态条件。

## 标准输出结构
1. 现象简述
2. 根因分析
3. 风险评估
4. 修改方案（遵循最小改动原则）
5. 回归测试步骤
